# 日志保留与清理

桌面主程序, Windows 输入服务与输入代理使用同一个日志轮转和清理模块. 每类日志独立执行以下规则:

- 单文件最多 1 MiB (1,048,576 字节).
- 最多 5 个文件, 包含 1 个当前文件和 4 个归档, 总容量最多 5 MiB.
- UTC 日期变化或下一次写入会超过单文件上限时轮转. 单次超过 1 MiB 的日志分片写入, 每个文件仍受大小限制.
- 删除超过 14 天的归档. 超出数量或容量时优先删除最早的归档, 同一天的编号按数值排序.
- 每个进程初始化日志时立即清理, 每次轮转后清理, 持续写入期间每小时再检查一次.

当前文件沿用原有名称. 主程序为 `synly.log`, 输入服务为 `service.trace.log`, 输入代理为 `input-agent.trace.log`. 新归档名称类似 `synly.2026-01-01.000001.log`.

升级后会识别旧主程序的日期和编号归档, 以及 Windows 服务与代理原有的 `*.trace.log.YYYY-MM-DD` 日志. 已有的超大当前文件会先归档, 清理时删除超过单文件上限的旧归档. 应用升级后首次启动会按新限制回收旧日志, 不需要手动删除.

清理仅处理当前日志文件对应的归档命名格式, 跳过符号链接, 目录和其他日志族. 删除失败的文件仍计入实际占用, 清理继续尝试其他旧文件, 下次检查会重试. 文件被占用或权限不足时, 容量上限可能暂时无法满足. 日志工作线程将清理和写入错误输出到标准错误, 每分钟最多报告一次, 避免向 tracing 队列递归写入.

主程序继续支持 `SYNLY_DATA_DIR` 与 `SYNLY_LOG_FILE` 路径覆盖. Windows 服务与代理仍使用各自进程身份的数据目录, 子目录分别为 `logs/service` 与 `logs/input-agent`. 每个进程维护自己的日志族, 主程序不尝试访问 SYSTEM 服务的日志目录.

桌面 GUI 日志列表最多保留 200 条, 清空按钮只清空列表. Android 应用内日志最多保留 500 条, 同时输出到系统 Logcat, 没有额外持久日志文件; 系统负责管理 Logcat 缓冲区.

上述限制针对应用的 tracing 日志. 自动更新安装器通过文件句柄或脚本直接写入的安装日志, 没有接入此轮转模块.
