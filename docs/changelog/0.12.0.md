# Synly v0.12.0

Date: 2026-09-28

本版本让 Android 端在重连时先复用最近连接过的对侧, 不必每次都重新扫描, 并让托盘的方向开关真正保留发送或接收这一侧设置. 音频与输入协议与 v0.11.1 兼容, 不必成对升级.

## Highlights

- Android: 主界面在扫描按钮之前直接列出最近连接过的对侧, 点一下就能连接, 不再等待发现.
- Android: 连接成功后记住实际使用的地址和对侧设备 ID, 下次后台恢复和断线重连优先用它, 失败才按设备 ID 重新发现.
- Android: 检测到默认网络切换为移动数据后等待 30 秒, 期间仍是移动数据就自动停止后台同步, 切回 Wi-Fi 会取消退出.
- 托盘: 剪贴板, 音频和输入三个开关改成子菜单, 可以直接选中关闭, 发送, 接收或双向, 而不是只能在开与关之间来回切.

## Upgrade Notes

1. 升级前不需要额外备份, 配置, 受信设备与身份密钥都在数据目录里, 安装与卸载不会触碰它.
2. Android 上首次启动会把旧版保存的 `last_target` 迁移进最近对侧列表, 旧配置无需手动处理.
3. 验证升级成功的方法: About 页显示 `v0.12.0`; 之后检查到新版本时, 安装落地后状态栏会提示 "已更新到 vX".

## Features

- Android: 最多保存 8 个最近连接过的对侧, 在扫描区顶部显示, 连接时不再需要先扫描; 主动断开只停止自动重连, 不会清掉这份历史.
- Android: 连接成功事件带回实际远端地址, 对侧设备 ID 和该地址会置顶保存, 后台恢复与断线重连优先尝试它.
- Android: 配置导出与导入会带上最近对侧列表, 没有该字段的旧备份会回退使用 `last_target`.
- Android: 默认网络持续为移动数据 30 秒后自动停止前台同步服务并释放连接, 切回非移动网络会取消退出计时.

## Bug Fixes

- 托盘: 之前剪贴板, 音频和输入在托盘里只有开与关两种状态, 发送切成关闭再打开会退回双向或接收, 忘记原本选的发送方向. 现在三个子菜单直接列出全部方向并勾选当前项, 不再经手开与关的映射.
- 托盘: macOS 自己会切换勾选标记, 点击后立刻重绘, 不再出现两个方向同时被勾选.
- 核心: 按设备 ID 重新发现目标地址时不再移动 `TcpStream`, 远端地址也从底层 TCP 流读取而不是 rustls 连接对象, 修复了 `synly-core` 在 Android 目标上编译失败的问题.
