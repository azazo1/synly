# Synly v0.10.0

Date: 2026-09-20

本版本重构桌面音频捕获, 编码, 传输和播放, 并让接收端可以选择立体声, 5.1 或 7.1. 两端桌面程序必须一起升级, 旧音频会话无法互通. Android 端仍不传输音频.

## Highlights

- 音频流水线: 捕获, 编码, UDP 传输和播放拆成独立工作线程, 使用有界队列; 设备掉线后可以重建捕获或播放, 不必重置传输状态.
- 接收声道: GUI 和配置新增立体声 / 5.1 / 7.1, 选择后下次连接生效, 不会把立体声源自动变成环绕声.
- 音频安全: 每次绑定生成新的通道标识, 使用按方向派生的密钥和防重放计数, 同一 TLS 会话重启音频时不会复用密钥和 nonce.
- 播放后端: 默认仍是 Windows WASAPI 与 macOS AudioQueue; 可选 `sdl2-audio` 按 Moonlight renderer 的排队和水位策略播放.

## Breaking Changes

- 音频 UDP: `AudioUdpReady` 现在必须携带 `channel_id`, 数据包使用 v2 密钥派生和认证数据. 迁移方式: 两端桌面同时升级到 v0.10.0; 与 v0.9.1 混用时可以发现设备, 但音频通道无法建立.
- 音频 UDP: 旧对端缺少 `channel_id` 的就绪消息会被拒绝. 迁移方式: 不要保留只升级一端的部署.

## Upgrade Notes

1. 先升级发送端和接收端, 再重新连接. 只升级一台电脑时, 文件和剪贴板仍可按协议 21 工作, 音频会失败.
2. 接收声道在设置页选择, 或在配置里写 `audio_layout = "stereo"`, `"surround51"` 或 `"surround71"`. 该字段缺省为立体声, 当前连接不会热切换布局.
3. macOS 系统音频捕获需要较新的系统音频 tap; 采集权限由系统提示. 可选 SDL2 播放需要本机提供 SDL2 开发库, 默认发布构建不启用该 feature.
4. 验证升级成功的方法: About 页显示 `v0.10.0`; 建立音频会话后, 接收端能听到发送端系统声音, 且设置页的接收声道与本次连接一致.

## Features

- 音频: Windows 与 macOS 的系统捕获和播放改为分阶段流水线, 捕获失败等待后重建设备并保留编码器, RTP 和加密状态; 播放失败后丢弃积压再重建输出.
- 音频: 接收端可选择立体声, 5.1 或 7.1, 并在就绪消息中声明; 发送端按声明选择编码器.
- 音频: 可选 `sdl2-audio` 播放后端, 对齐 Moonlight 的 float32 队列, 水位和设备停止检查.
- 打包: macOS 打包在发现未处理的 SDL2 动态依赖时拒绝生成不完整的应用包.
- 许可: 桌面音频随附 Sunshine 与 Moonlight 来源说明及 GPL 全文.

## Bug Fixes

- 音频: 应用其它设置时不再把尚未生效的接收声道写进当前会话; 能力确认也不会提前切换布局.
- 音频: 校正 Opus 参数, PCM 帧长度, RTP 同步和丢包恢复, 并限制播放队列积压.
- macOS: 拒绝无效的 tap 和聚合设备对象, 并在初始化失败时按顺序清理已创建资源.
- Windows: 修正 WASAPI 事件处理, COM 清理和 MMCSS 注册.
- CI: 发布工作流依赖升级到 Node 24 runtime, 避免旧 action 在 runner 移除 Node 20 后无法启动.
