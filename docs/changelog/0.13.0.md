# Synly v0.13.0

Date: 2026-10-10

本版本加入系统已配对设备之间的蓝牙连接, 桌面端与 Android 客户端都能使用, 并可与局域网绑定成同一个逻辑会话; 同时把同步范围收敛为剪贴板及其文件传输, 移除了目录同步. 协议升级到 22 且不向后兼容, 两端请一起升级.

## Highlights

- 新增蓝牙连接: 在系统蓝牙里完成配对的设备之间建立安全 RFCOMM 会话, 首次连接核对应用身份指纹后授权, 不使用第二组 PIN.
- 局域网与蓝牙可绑定为同一个逻辑会话, 输入和剪贴板各自选择允许的路径, 双方取交集.
- 移除目录同步, 保留剪贴板同步以及其中的文件传输.
- 桌面 host 支持多设备同时接入: 剪贴板在多会话之间广播, 音频与输入由单一活跃会话承载, 断开后自动提升其他已信任设备.
- macOS 触控板的滚动改为高分辨率滚轮转发到 Windows, 滚动更接近本机手感.

## Breaking Changes

- 协议版本由 21 升到 22, 两个版本之间不能互通. 使用旧版本的一端在配对阶段就会被拒绝, 表现为无法建立会话. 迁移方式: 把对端一并升级到 v0.13.0, 桌面端与 Android 端都要升级.
- 目录同步功能被移除, 不再有文件夹或文件的单向/双向同步, 删除同步与定时扫描一并去掉. `[runtime]` 下的 `file_sync_mode`, `paths`, `initial`, `sync_delete`, `interval_secs` 和 `max_folder_depth` 会在迁移时自动从配置里删掉. 迁移方式: 需要传文件时改用剪贴板同步, 剪贴板本身仍支持文件传输.
- 主配置 schema 由 4 升到 8, 启动时会自动迁移, 不需要手动改配置. 旧版本读不了新配置, 因此降级回 v0.12.x 之前请先备份配置.

## Upgrade Notes

1. 升级前不需要额外备份密钥: 身份密钥, 受信设备与配置都在数据目录里, 自动迁移会保留它们.
2. 桌面端与 Android 端都升级到 v0.13.0 后再连接. 只升级一端会停在"协议版本不匹配"的拒绝上.
3. 首次启动会自动把配置迁移到 version 8, 并移除目录同步相关配置项. 若配置里已经有高于 8 的版本号, 程序会拒绝启动并提示当前支持的版本.
4. 蓝牙接入默认关闭. 需要先在系统蓝牙设置里完成设备配对, 再在桌面 host 开启蓝牙接入; Android 端首次刷新蓝牙设备时会请求附近设备权限.
5. 音频仍然只使用局域网 UDP, 不会走蓝牙. 蓝牙主控制可以再挂一条局域网副承载来承载音频; Linux 目前没有蓝牙后端, Android 不提供桌面输入与音频能力.
6. 输入路径切换后需要按一次紧急收回热键 (默认 `ctrl+alt+shift+esc`, 可在设置里改) 确认, 再把鼠标移到屏幕边缘重新激活; 路径重建时状态栏与系统提醒会写出当前生效的热键.
7. 验证升级成功的方法: About 页显示 `v0.13.0`.

## Features

- 蓝牙: 支持 Windows, macOS 桌面端与 Android 客户端接入系统已配对设备. 桌面设备页提供已配对蓝牙列表, 手动刷新, 取消刷新与打开系统蓝牙设置; Android 首页提供已配对设备选择与权限申请.
- 蓝牙: 首次连接核对应用身份指纹并明确授权, 可选择保存信任. 系统配对记录, 设备名称与地址都不会自动变成 Synly 信任.
- 路径策略: 剪贴板和输入分别支持自动, 蓝牙优先, 仅局域网, 仅蓝牙. 策略取双方交集, 交集为空时只暂停该功能, 不影响主控制与另一项功能.
- 会话: 同一台设备的局域网与蓝牙可以绑定为一个逻辑会话, 主控制保持固定路径, 副承载随可用性接入或移除, 移除副承载不会关闭主会话.
- host: 多设备同时接入时剪贴板广播并做防回音与防洪流处理, 音频和输入由单一活跃设备承担; 界面提供会话列表, 逐个断开与手动切换活跃会话.
- 输入: 路径重建后会提示需要按哪个热键确认, 只在本机正在遥控对端时提示, 被控端不会收到无法照做的提示.
- 输入: macOS 触控板滚动以高分辨率滚轮事件转发到 Windows.

## Bug Fixes

- macOS 蓝牙: 服务查询改为在主运行循环派发, 先连接再查询未过滤的服务列表, 并在回调成功后等待链路状态, 修复了查询与连接反复失败的问题.
- macOS 蓝牙: 设备枚举拆到独立进程, 不再与应用主运行循环互相影响; 枚举期间不触发系统认证请求.
- macOS 蓝牙: 修复关闭 RFCOMM 通道时的过度释放, 该问题会让程序在连接建立后短暂时间内崩溃.
- macOS 蓝牙: 地址形式的目标可以复用本机已保存的任一条可用信任完成认证, 不再要求恰好只有一条记录.
- 输入: 本机输入压力较大时仍保持心跳, 避免被误判为链路超时.
- 输入: 输入辅助连接发送队列关闭时的错误分支判断修正.
- 路由: 只有双方都选"蓝牙优先"才主动切到蓝牙. 之前任一侧选择蓝牙优先就会改写对端的"自动保持健康路径", 使自动模式失去意义.
- 路由: 正在遥控对端期间不因偏好变化切换输入承载, 避免拆掉正在使用的输入子流并强制重新按热键确认.
- Android: CI 构建的 APK 改用 release 签名.
- Windows: 安装程序替换旧二进制后程序仍能正常响应.
- 界面: 修正蓝牙页面高度约束冲突, 压缩工具栏与设备行, 恢复刷新按钮原有文案.

## Performance

- macOS 蓝牙: RFCOMM 写从逐笔等待改为最多 8 笔在途, 通道缓冲允许时连续投递, 减少输入消息的串行等待. 该改动曾因真机崩溃回退, 在修正生命周期问题后重新启用, 实测尚未量化收益.
- 输入: macOS 触控板滚动的转发倍率调整, 在 Windows 侧的滚动速度更接近预期.
