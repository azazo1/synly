# Synly v0.9.1

Date: 2026-09-10

本版本修复 Windows 自动更新之后 SYSTEM 输入服务仍停留在旧版本的问题, 同时修好 Windows 上的分发与打包 recipe.

## Highlights

- Windows 更新: 就地替换 `synly.exe` 之后, 已安装的 SYSTEM 输入服务会在下次申请输入提权时重启并加载新版本, 不必重启电脑.
- Windows 更新: 旧映像仍被服务占用时, 备份改用 `synly.exe.old.<pid>`, 避免下一次更新因为无法备份当前程序而失败.
- 服务管理: 新增 `synly service restart` 命令.
- 构建: 修复 Windows 上 `just dist`, `just fake-dist` 与 `just debug` 因为 recipe 被交给 `sh` 执行而失败的问题.

## Upgrade Notes

1. 之前更新过一次的设备, 遗留的 `synly.exe.old` 会在应用启动时自动清理; 如果它当时仍被服务占用, 会在服务重启后的下一次启动中被清掉.
2. 服务重启需要一次 UAC 确认. 取消或失败都不会中断输入能力, 只是继续沿用当前服务, 下次申请输入提权时会再试一次.
3. 验证升级成功的方法: About 页显示的版本号应为 `v0.9.1`; Windows 日志在申请输入提权前会出现 "输入服务仍运行更新前的映像, 请求提权重启".

## Features

- 服务: 新增 `synly service restart`, 让输入服务重新从注册路径加载当前可执行文件.

## Bug Fixes

- Windows: 自动更新替换可执行文件后, SYSTEM 输入服务不再停留在更新前的映像上, 避免服务侧长期运行旧代码.
- Windows: 输入服务占用的旧映像备份不再阻塞后续更新, 更新失败时的回滚路径保持可用.
- 构建: Windows 的 `just dist`, `just fake-dist` 和 `just debug` 改用 `[script(...)]` 指定 powershell 执行, 修复 `$env:` 与 `$LASTEXITCODE` 被 bash 展开导致的 unbound variable 错误.
- 测试: 修正 `native.rs` 测试模块的导入路径, Windows 上的 `cargo clippy --all-targets --all-features` 与 `cargo test` 不再编译失败.
