# 蓝牙接入设计

本文记录目标设计与实现进度, 当前桌面与核心客户端已接入蓝牙业务复用, 桌面输入与剪贴板使用独立有界子流, 音频可使用实际绑定的 LAN 主/副承载地址, 尚未完成真实设备端到端与全部平台构建验证. 目标是在 Windows, macOS 和 Android 上支持系统已配对设备之间的 Synly 连接, 并允许各功能选择蓝牙或局域网. 剪贴板文件传输仍属于剪贴板通道, 不另设目录同步功能.

## 后端与发现

首版使用经典蓝牙 RFCOMM, 提供可靠的双向字节流并复用 TLS. BLE 自定义 GATT 暂不实现. 普通办公输入是优化目标, 不承诺固定刷新率或与硬件鼠标相同的延迟.

| 平台 | 原生接口 | 角色 |
|---|---|---|
| Windows | Win32 已配对设备枚举, SDP 查询/注册, Winsock AF_BTH + BTHPROTO_RFCOMM | host 和 client |
| macOS | IOBluetooth 已配对设备, SDP 与 RFCOMM | host 和 client |
| Android | BluetoothAdapter.bondedDevices, 安全的 BluetoothSocket, 按 UUID 查询 RFCOMM | client |

Synly 使用项目专用的 128 位服务 UUID `b392883b-e85b-4c92-b1a0-2cdfe0a7b6d4`. host 注册 SDP 服务并监听动态 RFCOMM 通道. client 查询系统已配对设备的 Synly 服务, 只有查询成功的设备进入可连接列表. 系统配对记录不代表设备在线. 自动重连优先查询上次成功端点, 失败后退避, 不在输入控制期间持续扫描.

UI 提供刷新已配对设备和打开系统蓝牙设置. 新设备由用户在系统设置完成配对. Synly 不实现蓝牙 PIN, 系统配对协议或解除系统配对, 不持续把本机设为可发现. 不支持经典蓝牙, 蓝牙关闭和权限拒绝应分别显示原因, 不能影响已有局域网功能.

## 身份与安全

安全 RFCOMM 已保护无线链路, TLS 不是蓝牙链路加密的必要条件. 保留 TLS 是为了复用 Synly 的长期身份认证, 应用授权和会话绑定, 而不是把系统配对记录直接当作应用信任. 系统已配对与当前连接已加密仍需分别验证.

Windows 在 connect/accept 前通过 `SO_BTH_AUTHENTICATE` 和 `SO_BTH_ENCRYPT` 强制安全要求, 系统拒绝无法满足要求的连接. 这两个选项不能用 getsockopt 查询, 不把配置值冒充成实际加密状态; 系统已配对记录仍单独校验. 参见 [Windows 蓝牙 socket 选项](https://learn.microsoft.com/en-us/windows/win32/bluetooth/bluetooth-and-socket-options).

已信任设备使用长期 mTLS. 未信任设备通过系统认证且加密的 RFCOMM 链路进行应用身份授权, 不要求第二组 PIN. 授权需要绑定当前 TLS 会话和双方身份, 显示身份指纹并保存长期公钥与证书. 不接受未配对或未加密链路的首次授权, 不自动降级到不安全接口.

蓝牙名称和地址只是发现线索. 认证前候选项可独立显示, 认证后按 device_id 与 identity_public_key 合并, 不按名称合并. 公钥变化时重新授权, 不自动覆盖信任. 撤销 Synly 信任关闭该身份的所有连接; 系统解除配对只停止蓝牙路径, 不删除局域网端点.

## 会话与路由

一个逻辑设备会话最多挂载一条局域网连接和一条蓝牙连接, 只有一个 host/client 角色和会话 ID. 第二条连接必须验证相同身份, 并通过绑定会话 ID, 有效期, 用途与 TLS exporter 的一次性挑战完成挂载. 重复连接在认证后消除, 不占用第二个活跃会话名额.

逻辑通道为 control, input, clipboard 和 audio. 主控制路径建立后保持稳定, 优先可用局域网, 没有局域网时使用蓝牙. 主控制断开时首版结束会话并重建, 不承诺无感接管.

| 路径策略 | 行为 |
|---|---|
| 自动 | 保留健康当前路径; 初次优先局域网, 再蓝牙 |
| 优先蓝牙 | 优先蓝牙, 允许局域网回退; 安全边界再回切 |
| 仅局域网 | 没有局域网就暂停, 不暗中回退 |
| 仅蓝牙 | 没有蓝牙就暂停, 不暗中回退 |

推荐输入优先蓝牙, 剪贴板自动, 音频仅局域网. 现有 UDP 音频暂不支持蓝牙, UI 禁用对应选项并说明原因. Android 仍受既有平台能力和系统剪贴板限制约束, 不因增加蓝牙而宣称支持桌面输入或音频.

双方允许路径取策略和平台能力的交集. 输入和剪贴板分别执行 Offer/Ready/Commit/Committed 协商, 修改剪贴板路径不暂停输入. 本机停止该通道并完成输入状态释放后才能发送 Offer 或 Ready. host 在发送 Commit 前准备新路径接收; client 收到 Commit 后准备接收, 发送并 flush Committed 后才能发送新路径数据; host 收到 Committed 后才能发送新路径数据. 这样其他更快链路上的数据不会因超越确认消息而丢失. 每个通道只生效一个路径, 通道包带路由代次和消息序号, 迟到的旧数据与重复数据不能重新生效. 策略冲突时暂停并显示原因, 不接受违反本机仅路径约束的方案. 单条非控制连接失败只处理其承载通道.

输入切换前释放接收端按键和按钮, 返回本地控制并丢弃旧位移. 新路径确认后由用户重新激活. 剪贴板按 transfer ID 去重, 对不完整载荷不写入系统剪贴板; 新路径只重传尚未确认的最新载荷. 音频恢复时重建通道和密钥.

## 剪贴板可靠交付基础

剪贴板帧新增稳定逻辑传输 ID, 单调消息序号和路径代次. 底层解析器仍能识别旧序号/代次 0 的帧, 新业务会话不接纳旧交付帧; 稳定交付帧必须具有非空 ID 和正序号/代次. 读入元数据后立即检查身份, 完整接收并验证所有块才返回载荷; 半包不会交付 OS. `ClipboardOutbox` 只保留最新未确认载荷, 路径重试共享同一载荷和 ID, 写入/flush 完成不会移除等待应用确认的载荷. `ClipboardInbox` 只在应用成功后推进去重状态, 同一消息号的冲突 ID/内容会拒绝, 丢失 ACK 后的重试只再次确认, 不再次应用. 摘要流式读取数据, 不额外复制文件和图片.

桌面接收端已接入稳定交付帧和异步实际应用回执, 仅接受实际已提交路径的当前代次. 慢 OS 应用或 host 中枢等待不阻塞控制/输入主循环. host 中枢为可靠事务返回 Applied, Failed, RateLimited, Superseded, QueueFull 或 Closed; 入队和内容 TTL 去重不冒充应用成功. 被更新载荷覆盖或取消订阅的等待事务不发送成功确认. 订阅/模式/取消事件不再与数据载荷一起合并覆盖. 应用失败不记入内容去重, 不广播失败载荷. 可靠交付检查单文件限制与全部缓存文件写入结果, 不允许部分写入后发送成功确认.

核心 client 提供带 delivery_id 的应用事件与 confirm_clipboard 命令, 等待调用方实际应用结果后才发送成功/失败回执. 过期和重复回执不推进事务, 已成功事务的重复帧不再次发出应用回调. Android 源码已将这个回执连接到 ClipboardWriter 的返回结果和异常处理, 并检查大小上限与完整缓存写入. 文件缓存与剪贴板应用在 IO coroutine 中执行, 不在 FFI 回调线程中等待磁盘/系统写入, 回执发给原客户端 handle, 不将迟到结果发送给另一个客户端. 绑定生成和 Android 构建未执行. 真实 mTLS 内存连接测试覆盖核心 client 在回调发出后不提前确认, 错误回执 ID 无效, 丢失 ACK 重试不再次应用.

发送端已经在桌面与核心 client 默认使用稳定交付帧. 独立发送任务通过单槽最新载荷邮箱接收本机更新, 当前已开始的帧完整写出后才发送最新载荷, 不在共享流上取消半帧. 等待应用确认不阻塞会话控制循环. 第一次写入完成后等待 15 秒, 随后按 30/60 秒退避, 每条载荷在同一路径上最多发送 4 次; 拒绝回执也使用相同有界退避, 不持续重试磁盘失败或策略拒绝. 重试保持 ID 与消息序号, 旧载荷迟到 ACK 不能清除新载荷. 关闭发送方向会清除等待事务, 即便快速关闭再打开被通知合并也不会重新发送旧事务. 已经开始写入的完整帧可继续到达, 接收端仍须校验当前接收权限. 新本机载荷可以开始新的有限尝试. 切换到新提交的路径时, 未确认载荷保留原 ID/消息序号, 使用新路径代次重新开始有限尝试. 单会话状态不会跨主会话重建持久化, 主会话结束仍重新建立会话.

认证后的 LAN 和蓝牙主承载均进入相同三通道复用层. 大剪贴板使用独立有界写入器和接收窗口, 不在 LAN 主控制原始流上串行写入大文件. LAN 主承载输入也使用相同四阶段 lease 协商, 蓝牙/局域网输入切换不再依赖新建辅助 TCP 来恢复主 LAN 输入. 旧辅助入口仍保留在源码, 新业务会话优先使用已准备的复用输入 lane. 实际核心 client mTLS 会话测试覆盖双向稳定交付与 ACK, 复用测试覆盖停顿 512 KiB 剪贴板时控制和输入继续进展.

剪贴板路由已接入桌面和核心 client 的独立四阶段 Offer/Ready/Commit/Committed. 主控制子流只允许控制帧, 剪贴板在已认证主/副承载中的独立 UUID lease 上传输. 接收端先准备有界 IO, client 在提交确认冲刷后, host 在收到确认后才允许可靠发送任务开始写入. 切换先同步撤销旧 lease, 丢弃旧读写任务, 再暂停发送任务并准备新 lease. 中途被截断的旧帧仅存在于被丢弃的旧流, 不会进入新 lease. 接收只接受实际提交的路由代次; 去重/待应用状态独立于物理路径, 丢失应用 ACK 后跨路径重发不会重复应用已经成功的载荷. 路径握手限时 10 秒, 失败只暂停剪贴板, 相同能力/策略/可用路径状态不持续重启失败协商. 旧代次确认/失败/Offer 不影响新路径. Auto 保留健康当前路径, 副承载丢失后重新协商仍可用的允许路径; 不自动重建已经结束的主会话. 当前默认策略 Auto, 桌面剪贴板设置可选择 Auto/蓝牙优先/仅局域网/仅蓝牙. 配置独立 v7 -> v8 migration 默认 Auto, 保留已有策略与文件大小/缓存限制. 在线修改经主控制单调状态代次公布并取双方交集, 仅切换剪贴板, 不重建主连接或输入; 没有允许在线路径时保留最新等待载荷, 路径恢复后继续协商. 桌面会话列表显示剪贴板实际已提交路径, 协商, 策略冲突/不可用与失败暂停状态. 双向丢失 ACK 换路径, 副承载移除, 策略冲突暂停与恢复, 丢失 Commit 和 256 KiB 半帧中断恢复均已通过无硬件测试.

## 音频 LAN 路径

音频始终为 LAN UDP, 不在蓝牙 mux 中建立音频 lane. 蓝牙主控制可使用完成身份认证和会话绑定的 LAN 副承载. 只保留本机 TCP socket 的实际对端地址, 不采纳发现广播或控制消息提供的 IP. 双方以同一个已证明的绑定 nonce 作为路径 ID, 音频密钥从主 TLS 音频 exporter 和完整路径 ID 派生, 然后再使用接收端随机 channel_id 派生通道密钥. 新 LAN 绑定即使使用相同地址与 channel_id 也不能接纳旧密文.

主控制上的 AudioUdpReady 带能力代次, 路径 ID, 端口和 channel_id. 仅当前已绑定且双方公布在线的 LAN 路径可准备 UDP. 旧路径消息, 端口 0, 空 channel_id 与过期能力消息不会启动发送. LAN 副承载移除或路径改变先停止音频并重新准备接收端. 等待端口最多 10 秒; 音频任务或设备失败只暂停音频并通过主控制通知对端, 不终止输入, 剪贴板或主会话. 相同失败状态不会不断启动捕获/播放设备, 路径或能力变化后才可恢复. Android 仍不提供音频能力.

无硬件测试覆盖双方绑定 ID 一致, 本机地址随副承载交付, 缺少实际地址/对端在线状态不启动音频, 旧准备消息不启动发送, 路径丢失与失败恢复门槛, 新路径密钥拒绝旧密文, 以及正常/异常监督任务只收集一次. 不代表蓝牙与音频硬件互通已经验证.

## RFCOMM 复用与调度

一条 TLS over RFCOMM 连接通过小尺寸通道包复用. 包含 channel ID, 路由代次, 消息 ID, 分段标记和长度. 长消息在进入 TLS 写入器前分段, 不重排已生成的 TLS 密文.

调度优先级为控制确认与状态释放, 输入按键/按钮和位移, 剪贴板元数据与文本, 剪贴板图片/文件. 各通道使用有界队列与接收窗口, 高优先级也有限额, 避免大载荷永久饥饿. 磁盘写入不能阻塞输入读写.

初始验证可试用 1-4 KiB 的大数据片段和 60-125 Hz 的鼠标位移发送上限. 合并未发送的相对位移和兼容滚动, 不跨按钮/按键边界重排, 不合并按下/释放. 队列溢出时先结束远程输入状态再恢复. 现有 1 MiB 剪贴板块不能直接作为共享蓝牙调度粒度.

## 模块边界与验证

当前核心已实现类型擦除字节流, 1 KiB 分片与独立接收窗口的复用层, 以及 macOS 的 IOBluetooth 已配对设备枚举, SDP 查询/注册和 RFCOMM 桥接. 原生连接校验配对与加密, 使用有界 socket 缓冲和回调队列, 关闭时注销服务或取消通道. `just bluetooth-native-test` 使用假通道和内存检查器验证原生桥接, 不访问真实蓝牙设备.

Windows 原生后端源码已接入核心平台选择, 包括 WinRT 控制器状态, Win32 系统配对记录, SDP 查询/注册和强制认证/加密的 Winsock RFCOMM. 阻塞 IO 桥接限制为 1 KiB 写片段和两个接收队列片段, flush 等到原生写完成, 取消时关闭 socket 并唤醒读写. 平台无关桥接已经在 macOS 验证, Windows 源码已核对 SDK 绑定并通过语法解析, 但尚未进行 Windows 构建或真实设备测试.

Android 安全 BluetoothSocket 与 UniFFI 提供者声明已接入核心平台选择和应用初始化. 只枚举系统已配对设备, 按 UUID 查询服务并创建安全 RFCOMM socket, 不回退到不安全接口或固定通道反射. 已声明附近设备权限, 设置连接/写入超时, 并在配对移除或关闭蓝牙时关闭 socket. 取消连接和外部读取越界由平台无关提供者测试验证. Android 公开 UUID 接口不返回 RFCOMM 通道号, 因此端点通道为可选值, 不使用伪造的通道号.

Android 的持续设备通信前台服务使用 connectedDevice, 清单声明 FOREGROUND_SERVICE_CONNECTED_DEVICE, 启动时明确传入对应类型. 此类型适用于蓝牙和网络外设通信, 既有 CHANGE_WIFI_MULTICAST_STATE 声明满足其启动前提之一; 蓝牙 socket 仍必须取得附近设备权限, 不使用前台服务权限替代蓝牙授权. 不混入 dataSync 类型, 避免将持续外设会话计入 Android 15+ 的 dataSync 后台 24 小时内累计 6 小时时限. minSdk 29 已支持三参数 startForeground 与该服务类型, targetSdk 36 保持不变. 清单结构和调用已核对, Android 14/15/16 的实际服务启动, 权限撤销及后台运行仍需远端构建和设备验证. 参见 [Android connectedDevice 类型与启动前提](https://developer.android.com/develop/background-work/services/fgs/service-types?hl=en#connected-device) 和 [前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout?hl=en).

核心客户端的 stop_and_wait 等待独立的持久完成信号, 不把命令队列关闭当作任务已退出. 工作任务拥有完成 guard, 正常返回, panic 或取消时都会在退出清理后触发信号, 多个等待者和完成后的再次等待都可返回, 不存在瞬时通知的检查/注册丢失唤醒窗口. 无硬件测试覆盖队列先关闭仍等待清理, 并发与迟到停止调用, 以及真实核心工作任务中外部监听器 panic 后释放资源并完成等待. 该测试在本机默认 Rust 核心上执行, 不编译 FFI/Android 或跨平台目标.

现有 `just android-build` 会先执行 `android-core`, 从目标动态库重新生成 Kotlin 绑定再构建应用. 新增回调和类型必须经过该步骤; 没有在本机运行 Android 构建, 绑定生成或 Android/JNI 测试, 尚未完成真实设备互通验证.

公共 Rust 核心负责 transport, mux, 路由协商与身份认证. 原生层只负责系统蓝牙 API. Android 通过 UniFFI 接入有界数据桥, 后台读取 BluetoothSocket, 取消时关闭 socket 并唤醒阻塞 IO. TCP 的 nodelay 和音频对端 IP 只属于局域网后端.

配置已持久化接入开关和输入路径策略, 通过独立 v6 -> v7 migration 添加蓝牙优先的默认输入策略, v7 -> v8 添加 Auto 剪贴板策略, 不改变剪贴板文件大小/缓存限制. 应用版本未更改. 桌面会话状态 UI 已显示已接入承载和输入/剪贴板/音频路径. 输入接收端的活动标记覆盖真实激活期并在退出/取消时清除, 因此作为接收端被控制时也暂停新的候选扫描. 日志使用 tracing, 记录发现变化, 服务注册, 认证耗时, 路由生效和失败原因, 不记录密钥, attach token 或剪贴板内容.

本机 aarch64-apple-darwin 已通过默认原生音频后端的 release/offline/locked 构建. 组装的应用包已通过 plist 解析, 蓝牙用途说明与 bundle ID 检查, CLI --help 正常退出且没有目录同步选项, 二进制为 arm64 Mach-O. 这是构建验证包, 未安装或启动 GUI, 未注入正式发布版本, 不代表系统蓝牙权限交互或真实互通已验收. DMG 创建未完成: hdiutil 的 APFS 磁盘节点格式化被 workspace-write 沙箱阻止, 详细诊断确认 Operation not permitted; 不将最初的目录非空错误误判为输出目录冲突. Windows/Android 构建与生成绑定仍未验证, 本机没有运行 Android 工具或交叉编译.

验收需要覆盖 Windows-macOS 双向连接, Android 到两种桌面端, 双路径单会话, 仅路径约束, 蓝牙大剪贴板载荷期间输入响应, 断线状态释放, 重启服务注册和权限变化. 不在本机运行 Android 或交叉编译. 系统接口可用不代表设备互通与性能已验证.
